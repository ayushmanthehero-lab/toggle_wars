# CI Guard Implementation Plan

> **For agentic workers:** Use focused parallel agents for independent components, then integrate and independently review. Steps use checkbox syntax for tracking.

**Goal:** Deliver the full self-hosted CI Guard workflow and dashboard described by the user.
**Architecture:** One coordinator persists decisions and atomically reserves shared retries. A CLI/action runs tests. Flagsmith supplies runtime policy. React displays actual evidence.
**Tech Stack:** Python 3.12, FastAPI, SQLite WAL, pytest, React/TypeScript/Vite, Docker, self-hosted Flagsmith.
**Spec:** `docs/superpowers/specs/2026-11-21-ci-guard-design.md`.

## Global constraints
- Blocked never passes. Unknown and assertion failures never receive infrastructure retries.
- Concurrent retries require atomic reservations and idempotency.
- No secrets in reports or browser bundles. No invented metrics or savings.
- Explicit demo mode, single coordinator/local SQLite disk, actual live Flagsmith policy reads.
- User supplied full product scope and authorized implementation; retain implementation choices as documented decisions.

## Review focus
- Duplicate attempt requests and client crashes must not create extra retries.
- Mode changes and recovery must not reset budgets silently.
- Failed or stale policy evaluation must not fabricate an enforce decision.
- Command timeouts/signals must terminate child processes and preserve failure.
- Empty/disconnected UI must not appear to show healthy production traffic.

## Tasks
- [x] Coordinator: write budget/concurrency/idempotency/auth tests, verify failure, implement transactional persistence and HTTP contract, run full backend suite.
- [x] Runner/action: write subprocess/classification/report/exit tests, verify failure, implement argv execution and GitHub composite wrapper, run runner suite.
- [x] UI: implement API client and reference-inspired functional screens, typecheck/build, test meaningful filtering/dialog/error state behavior in browser.
- [x] Infrastructure: Docker/Flagsmith bootstrap, pinned Python and npm dependencies, configured demo service, run instructions and operational guide.
- [x] Integration: actual local API/runner, four concurrent jobs in observe/enforce, assertion/unknown/healthy recovery scenarios, actual Flagsmith changes.
- [x] Release review: independent code review, focused corrections, full tests/build/browser, update evidence and user-facing limitations.

See `docs/VERIFICATION.md` for observed results and the remaining external GitHub validation. Completing this local implementation does not certify a remote release or branch-protection configuration.

## File ownership
Coordinator agent owns `server/` and server tests. Runner agent owns `runner/`, `action.yml`, and runner tests. UI agent owns `web/`. Root owns infrastructure, example service, scripts, docs, root configs and integration tests. Share schema changes explicitly; do not edit another owner's files without coordination.
